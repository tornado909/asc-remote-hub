# ASC Remote Hub

**Универсальный MCP-хаб для ChatGPT, Cursor, OpenMausBot и других MCP-клиентов с агентами Windows и Linux.**

Позволяет работать с файлами, терминалом, процессами и, если имеется интерактивный рабочий стол, экраном удалённого компьютера. Трафик проходит через **ваш HTTPS-сервер**, без платного ретранслятора Desktop Commander и без OpenAI Platform Tunnel.

[English README](README.md) · [Установка сервера](docs/DEPLOYMENT.md) · [Безопасность](SECURITY.md) · [GUI без вмешательства](docs/WINDOWS_GUI.ru.md) · [Изолированный GUI Engine без VM](docs/ISOLATED_GUI.md) · [Мост ASC Game Agent](docs/GAME_AGENT.md)

> [!IMPORTANT]
> Проект независимый, не связан с OpenAI или Desktop Commander. У хаба нет платных квот на команды; **ограничения ChatGPT** зависят от вашей подписки и поддержки пользовательских MCP-инструментов. Хостинг и домен вы оплачиваете или содержите самостоятельно.

## Возможности

- Свободная регистрация, личные устройства и изоляция данных пользователей.
- Независимая от конкретного приложения авторизация MCP через OAuth 2.1, PKCE и Dynamic Client Registration.
- Исходящие HTTPS-соединения от агента — открывать порт на своём ПК не нужно.
- Чтение, запись и поиск файлов, безопасная точечная замена текста, запуск программ и контроль процессов.
- GUI Windows: адресная работа через UI Automation с проверкой HWND/PID; физический ввод мышью и клавиатурой в агенте 1.1.1 по умолчанию запрещён.
- **ASC Game Agent (эксперимент):** разрешения в трее Windows, выбор окна по HWND/PID, захват WGC/DirectML с отдельным локальным подтверждением; автономного управления играми пока нет. [Подробности](docs/GAME_AGENT.md).
- GUI Engine 1.1.2: создание отдельных Win32 Desktop, запуск EXE без VM, фоновое управление стандартными контролами, PrintWindow-захват, уборка процессов через Windows Job Object.
- Отдельный сворачиваемый журнал ошибок и счётчики вызовов.
- Полная запись запросов/ответов выключена по умолчанию; при включении ведётся для всех авторизованных аккаунтов с разделением по пользователям и устройствам.
- Установка агента одной командой с вашего домена.

## Развёртывание хаба

Нужны Linux, Docker Compose, собственный домен и HTTPS:

```bash
git clone https://github.com/tornado909/asc-remote-hub.git
cd asc-remote-hub
cp .env.example .env
```

Укажите в `.env`:

```dotenv
ASC_HUB_URL=https://hub.example.com
ASC_HUB_DOMAIN=hub.example.com
ASC_BIND_IP=127.0.0.1
ASC_BIND_PORT=18765
PUID=1000
PGID=1000
ASC_HUB_TRACE_PAYLOADS=0
```

ASC_HUB_TRACE_PAYLOADS=1 включает полную трассировку команд и ответов всех авторизованных пользователей, 0 — отключает её. Журналы разделяются по аккаунту и устройству, токены авторизации не сохраняются. В тестовом стенде все участники должны знать, что записываются тексты команд и файлов.

Затем:

```bash
mkdir -p data && chmod 700 data
docker compose up -d --build hub
```

Настройте внешний HTTPS reverse proxy с маршрутом на порт `18765` либо используйте включаемый профиль Caddy (если порты 80/443 свободны). Все OAuth-ссылки и скачиваемые установщики формируются автоматически по **`ASC_HUB_URL`**, без изменения исходников.

## Установка агента

Откройте кабинет на своём хабе, создайте аккаунт, нажмите «Добавить устройство» и получите одноразовый код.

В Windows PowerShell:

```powershell
npx --yes https://hub.example.com/cli.tgz
```

В Linux:

```bash
npx --yes https://hub.example.com/cli.tgz
```

### Автоматическая установка зависимостей

Если Node.js/npx или Python отсутствуют, в кабинете есть отдельные команды установки зависимостей и скачиваемые сценарии bootstrap.ps1 (Windows) и bootstrap.sh (Linux). Скрипты берутся с вашего HTTPS-хаба, проверяют текущие версии, при необходимости устанавливают Node.js, npm, Python и venv, затем запускают существующий установщик агента. Код привязки вводится вручную.

Windows 10/11: WinGet. После скачивания bootstrap.ps1 запустите его из PowerShell через powershell.exe -NoProfile -ExecutionPolicy Bypass -File. Параметр -DependenciesOnly устанавливает только зависимости, -CheckOnly ничего не устанавливает.

Linux: apt (Debian/Ubuntu), dnf/yum (Fedora/RHEL), zypper (openSUSE). Запустите скачанный файл командой bash bootstrap.sh. Параметр --deps-only устанавливает только зависимости, --check только проверяет. Требуются sudo/root для системных пакетов и подходящий дистрибутив с Node.js 18+ и Python 3.10+. Сторонние репозитории автоматически не добавляются.

Выполняйте сценарии только с доверенного хаба; скачанный файл можно предварительно просмотреть. Старые привязки сохраняются стандартным установщиком.
**Linux (рекомендуется, без npm):** новый bootstrap скачивает только необходимые пакеты ОС (Node.js 18+, Python 3.10+, tar и curl/wget), получает актуальную `cli.tgz` с хаба и запускает её напрямую через Node.js, сохраняя интерактивный ввод кода. Выполните команду подключения, показанную на своём хабе, или скачайте `/bootstrap.sh` и запустите `bash bootstrap.sh`. Поддерживаются `--check` (без установки), `--deps-only` (только зависимости), `--verify-cli` (версия скачанного CLI) и `--cli-dry-run` (проверка архива). Команды `--unpair` и `--uninstall` также работают без npm.

На Debian/Raspberry Pi OS **не нужно устанавливать пакет `npm`**, если вы пользуетесь bootstrap: он может подтянуть сотни ненужных пакетов. Старая команда `npx --yes .../cli.tgz` продолжает работать, когда npm/npx уже есть. На новых Linux `/tmp` и домашний каталог могут находиться на разных разделах: CLI 1.1.5 собирает проверенные файлы на целевой файловой системе и больше не вызывает `rename` между разделами.
**Windows:** агент теперь работает в системном трее без открытого терминала. По правому клику доступны «Открыть хаб», «Перезапустить агент», «Выход». Выход останавливает агент до следующего входа в Windows или ручного запуска задачи. Привязка и ключ при этом сохраняются. Журналы агента: `%LOCALAPPDATA%\\ASC-Remote-Hub\\logs`.

**Linux:** под обычным пользователем устанавливается пользовательский systemd-сервис, под `root` — системный `/etc/systemd/system/asc-remote-hub-agent.service`. При полном доступе команды хаба выполняются от `root` — используйте это только осознанно на доверенных серверах.

Установщик проверит SHA-256 архива, попросит выбрать разрешённые каталоги и уровень доступа, затем получит код привязки. Нужны Node.js 18+, Python 3.10+ и tar. Node.js нужен только для установки. `--dry-run` проверяет готовность без изменения компьютера.

## Подключение ChatGPT

Добавьте свой MCP-сервер:

```text
https://hub.example.com/mcp
```

Выберите OAuth и войдите в свою учётную запись хаба. У каждого пользователя отдельные устройства и права.

## Важные ограничения

Полный доступ даёт возможность запускать на компьютере произвольные программы от имени пользователя агента. Настраивайте разрешения осознанно. Владелец сервера с административным доступом технически может видеть передаваемые данные; сквозного шифрования от администратора здесь нет.

После перезапуска агента старые ID фоновых процессов могут стать недоступны. Вызовы на одном устройстве могут выполняться последовательно. Для больших файлов предусмотрены ограниченные операции; не используйте их вместо системы резервного копирования или полноценного файлового транспорта.

Подробности — в [README на английском](README.md), [руководстве](docs/DEPLOYMENT.md) и [политике безопасности](SECURITY.md).

## GUI Windows без захвата курсора (агент 1.1.1)

Предпочтительная схема: window_list → window_controls → window_action. Физический ввод по умолчанию запрещён даже при полном GUI-доступе; изменяющие UIA-действия не выполняются, пока пользователь активен. Подробности в [документации](docs/WINDOWS_GUI.ru.md).

## Возможности версии 1.1.0

**Исторический интерактивный сценарий Windows Terminal / Codex (1.1.0):** window_list → window_focus → terminal_send → window_screenshot. В версии 1.1.1 такой ввод дополнительно требует локального разрешения администратора и отдельного подтверждения каждого вызова. Для работы с CLI рекомендуется run_command, не затрагивающий пользовательский GUI.

**Чтение проектов:** read_files (до 16 файлов), stat_paths (до 64),
directory_tree (до 250 элементов), search_text (ограниченный буквальный поиск).
Все файловые операции соблюдают ASC_RC_ROOTS и не переходят через симлинки.

**Диагностика:** авторизованный /api/performance?hours=24 и MCP
performance_stats показывают задержки очереди/агента/ретрансляции.
Статистика хранится не более 7 суток. Полные журналы трафика, если включены,
остаются изолированы по пользователям и устройствам.

**Развёртывание:** один стабильный установочный адрес
npx --yes https://hub.example.com/cli.tgz. Уже установленный агент
не меняет локальные DPAPI-ключи и разрешения при обновлении файлов.
Если npm использует старую кешированную версию, проверяйте баннер
установщика и актуальный архив /cli.tgz; не удаляйте регистрацию наугад.


## Универсальные MCP-приложения (сервер 1.2.0)

Адрес подключения для ChatGPT, Cursor, OpenMausBot и других HTTP MCP-клиентов:
https://hub.example.com/mcp

Cursor: добавьте запись asc-remote-hub с полем url = https://hub.example.com/mcp
в существующий объект mcpServers файла C:\Users\<имя>\.cursor\mcp.json.
Не удаляйте уже настроенные MCP-серверы.

OpenMausBot: укажите удалённый Streamable HTTP MCP URL и включите OAuth.
В браузере авторизуйтесь с логином и паролем ASC Remote Hub. PKCE S256 обязателен.

OAuth-регистрация клиентов: HTTPS callback для web-приложений;
локальные desktop callback только на localhost / 127.0.0.1 / [::1] с портом.
Каждый клиент получает свои токены, но видит только устройства владельца.

В кабинете: «Авторизованные MCP-приложения» позволяет отозвать доступ
отдельного приложения без отключения других клиентов или агентов.

Версия Hub 1.2.0; агенты/CLI остаются на 1.1.0, переустановка не нужна.
CIMD (Client ID Metadata Documents) пока не включён: нужна регистрация DCR.


## Отвязка / удаление на Windows и Linux

На **том компьютере**, где установлен агент, запустите:

```text
npx --yes https://hub.example.com/cli.tgz unpair
npx --yes https://hub.example.com/cli.tgz uninstall
```

Замените адрес `https://hub.example.com` своим HTTPS-адресом. На сайте команды формируются автоматически.
`unpair` отзывает ключ только данного устройства на хабе, останавливает сервис/задание и удаляет локальный ключ; установленные файлы остаются для подключения к новому хабу.
`uninstall` дополнительно удаляет установку, настройки и журналы пользователя.
Обе операции требуют подтверждения в локальном терминале; через меню трея Windows доступен тот же функционал.
Сначала выполняется отзыв ключа на хабе; если сервер недоступен, операция по умолчанию не удаляет локальные данные.
`--local-only` разрешает только локальное отключение без серверного отзыва: после него необходимо отдельно отозвать старое устройство в веб-кабинете.
`--dry-run` показывает план без изменений.
Кнопка «Отвязать» в веб-кабинете отзывает ключ на сервере, но не удаляет файлы и не выключает автозапуск на клиенте.
Управление одной машиной не затрагивает другие устройства пользователя.
