# ASC Game Agent: Universal Perception Core v21

**Принцип:** агент универсален для любых игр и графических приложений.
Названия игр, персонажей, NPC, палов и предметов не зашиваются в ядро.
Palworld остаётся только проверкой захвата WGC/DirectML.

**Статус:** интерфейс asc.game_agent.scene.v1 и универсальный трекер
метаданных реализованы. Реальные open-vocabulary, VLM и GPU OCR
провайдеры ещё не установлены. Native v19 пока выдаёт лишь
диагностические значения COCO person/bus и НЕ способен понимать
произвольные игровые сцены.

## Как должна работать архитектура

    Selected window (HWND/PID/start or another platform's source identity)
        -> native local user consent
        -> WGC GPU frame (no CPU fallback)
        -> Provider Registry (GPU local / optionally trusted GPU worker)
        -> open-vocabulary detector + VLM + OCR/UI grounder
        -> universal scene schema + uncertainty
        -> temporal tracker + short session memory
        -> planner (observe, reason, propose, verify)
        -> action adapter (separately authorized, not implemented)

Vision-провайдер выбирается по доступным возможностям и свободной VRAM.
Новый незнакомый объект хранится как **unknown**, а не переводится
принудительно в известный класс. Произвольные подписи объектов и
тексты UI сохраняются на исходном языке. Отдельной тренировки
нейросети под каждую игру не требуется.

Исследуемые взаимозаменяемые реализации:
- OmniParser: обнаружение интерактивных UI-регионов.
- Qwen3-VL и другие VLM: общее понимание сцены, связей и контекста.
- Open-vocabulary detector (YOLO-World / Grounding DINO): поиск по
  произвольным текстовым запросам.
- OCR: надписи, названия кнопок и подсказки.
Это кандидаты, ни один из них данным изменением не устанавливается.

## Контракт сцен

Реализовано: **client/asc_game_agent_scene.py**.

Схема: **asc.game_agent.scene.v1**. Источник идентифицируется
универсально, без Win32/Unreal-зависимостей:

- FrameIdentity: source_kind, source_id, source_generation,
  frame index, frame width/height;
- ProviderCapabilities: name, model, open_vocabulary, ui_grounding,
  ocr, temporal_reasoning, gpu_inference;
- entities: свободный label, универсальный kind, нормализованный
  bbox [x1,y1,x2,y2], confidence либо null, optional OCR text,
  interactive (true/false/null), state;
- relations: ссылки на ID объектов, произвольное название отношения;
- summary и uncertainties: естественный язык;
- raw_image_included=false, action_authorized=false, input_sent=false.

Допустимые универсальные kind: object, agent, terrain, ui, text,
effect, unknown. Это ТИП представления, не игровые классы.

Текст с экрана считается недоверенным: даже если он выглядит как
инструкция для модели, Planner не обязан ему следовать.
Неизвестные поля (например raw_image, command, URL или model_path),
NaN, невалидные bbox, повторные ID и сломанные отношения отклоняются.
Контракт не выдаёт разрешений на управление и не открывает окно.

TemporalSceneTracker сопоставляет видимые объекты по IoU
нормализованных рамок и сохраняет краткосрочный ID. Трек не
считается доказательством семантической идентичности; при смене
source_generation он сбрасывается. Для быстро движущихся объектов
нужен более мощный трекер в будущем.

| Локальное подтверждение захвата | Работает: v19 |

| Универсальный Scene Contract | Реализован как чистый Python |

## GPU и безопасность

На ASCENTO-PC в момент проверки, когда Palworld был запущен,
на RTX 4060 оставалось около 4 ГБ свободной VRAM из 8 ГБ.
Нужно оставлять дополнительный запас для игрового рендера.
Модель на 8B не следует загружать без профильного теста памяти,
учитывающего активации, KV-cache и влияние на игру.

По умолчанию кадры остаются на локальном GPU. Сегодняшний v19
не выдаёт другому Vision-провайдеру универсальный GPU frame handle,
поэтому настоящая семантика требует новой нативной интеграции.
Передача полноразмерного кадра на ASC-AI или любой другой хост
не разрешается автоматически: она требует отдельного согласия,
явного включения маршрута и защиты передачи. Не считать
GPU-инференс на сервере эквивалентом нулевого CPU readback клиента.

Ни распознанный текст, ни семантика сцены не служат разрешением
на игровые действия. Никаких автоматических SendInput, DLL injection,
обхода античита, запуска игры или скрытого доступа не добавляется.
CPU inference fallback запрещён.

## Критерии приёмки будущего Vision

Без изменения весов/кода под конкретную игру проверить
минимум три неизвестные игры и одно обычное графическое
приложение с разными разрешениями и HUD. Проверить:
- свободные текстовые категории и явные unknown;
- интерактивные области, OCR и локализацию координат;
- смену HWND, процессной идентичности, размера окна;
- удержание ID при небольшом движении и сброс при смене цели;
- отказ при отсутствии прав или VRAM;
- влияние на FPS игры, peak VRAM, отсутствие CPU fallback;
- отсутствие передачи кадров и ввода без разрешения.

Следующий технический блокер: реализовать **GPU-frame provider
interface** с прямой передачей D3D12 текстуры или GPU тензора
универсальному OCR/VLM/detector backend. До этой реализации
ядро принимает только синтетические метаданные из тестов,
и выводить «универсальное распознавание готово» запрещено.
