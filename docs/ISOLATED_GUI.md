# ASC GUI Engine 0.1: изолированные Win32 Desktop без VM

**Релиз агента:** ASC Remote Hub 1.1.2
**Среда:** Windows 10/11, Python 3.10+, доступные средства Win32 и Windows Job Object.

## Цель

ИИ управляет своими GUI-приложениями в отдельном Windows Desktop, **не затрагивая курсор, фокус и ввод пользователя**. Это не Hyper-V, не вторая ОС и не самостоятельная сессия Windows. Ресурсы расходуются лишь на окна и процессы самих приложений.

Экспериментально проверено на ASCENTO-PC, Windows 11: создание Desktop, `CreateProcessW` с корректным `STARTUPINFO.lpDesktop`, перечисление окон, `WM_SETTEXT`, `BM_CLICK`, `PrintWindow` и гарантированная очистка через Job Object. При тестах пользовательский курсор и активное окно не менялись.

**Важно:** отдельный Win32 Desktop изолирует графические объекты, но **НЕ** является границей безопасности для запуска недоверенного ПО. Приложения запускаются под тем же пользователем и обладают его доступом к файлам/сети. Защита от вредоносного ПО не входит в задачу.

## Схема управления

1. `gui_desktop_create` создаёт Win32 Desktop с непрогнозируемым именем ASC_GUI_<id> (не более 3 на агента).
2. `gui_desktop_launch` запускает указанный EXE со списком аргументов напрямую через Win32 `CreateProcessW`. Процесс назначается в Windows Job Object **до начала выполнения**, чтобы его потомки завершились при остановке управляющего агента.
3. `gui_desktop_windows` перечисляет HWND, PID, класс, заголовок и границы элементов. Отображаются только окна процессов, запущенных этим GUI Engine (первоначальный лимит: 6 корневых процессов на Desktop).
4. `gui_desktop_action` выполняет действия строго по HWND и PID в принадлежащем Desktop. Пока поддерживается `set_text` для обычного Edit через `WM_SETTEXT` с чтением результата, `click_button` для стандартного Button через `BM_CLICK`. Подмена PID, чужой HWND и неправильный класс отклоняются.
5. `gui_desktop_capture` выполняет `PrintWindow` в контексте рабочего стола, возвращает PNG base64 и признаки `printwindow_returned` и `uniform_image`. **Чёрный/пустой кадр нельзя выдавать за полноценный результат.** Для GPU-приложений PrintWindow может не работать; захват DirectX будет отдельной задачей.
6. `gui_desktop_sessions` перечисляет только созданные текущим агентом Desktop.
7. `gui_desktop_close` завершает принадлежащие процессы, закрывает Job Object и Desktop.

Вместо общего ввода **никаких** `SendInput`, `SetCursorPos`, `SwitchDesktop`, `pyautogui` и виртуального HID.

### Пример вызовов (псевдокод)

```text
gui_desktop_create(device)
 -> desktop_id

gui_desktop_launch(device, desktop_id, program="C:\\Path\\test.exe", args=[])
 -> pid

gui_desktop_windows(device, desktop_id)
 -> windows[]  // hwnd, pid, class_name, title, parent_hwnd

gui_desktop_action(device, desktop_id, hwnd, expected_pid, method="set_text", text="hello")
gui_desktop_action(device, desktop_id, hwnd, expected_pid, method="click_button")
gui_desktop_capture(device, desktop_id, hwnd, expected_pid, max_width=1000)
gui_desktop_close(device, desktop_id)
```

## Политика и границы

- Все новые инструменты работают только если у Windows-агента есть **и** `ASC_RC_ALLOW_GUI`, **и** `ASC_RC_ALLOW_EXEC`. Существующие разрешения на ввод в общий рабочий стол **не расширяются**.
- Путь до EXE указывается абсолютно; запуск без shell. Объекты создаются внутри уже разрешённой Windows-сессии.
- Нельзя воздействовать на HWND/PID чужих процессов; для кнопок/редакторов разрешены только проверяемые классы стандартных контролов. Парольные Edit поля отклоняются.
- Лимит 3 Desktop × 6 корневых процессов, размер окна для захвата ограничен, размер ответа PNG максимум 2 МБ. Блокирующие Win32 действия ограничены по времени.
- Утечка GUI-процессов после аварийного завершения менеджера предотвращается `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`. Это отдельно подтверждено тестом с принудительной остановкой владельца.
- Запуск игры может не работать: Raw Input, DirectInput, DirectX, отдельные процессы лаунчера и WGC требуют дальнейшего исследования. **Совместимость с играми пока не подтверждена.**
- `PrintWindow` иногда рисует чёрное или устаревшее изображение; в таких случаях результат помечается как ненадёжный.
- GUI Engine пока не предназначен для скрытого управления чужими машинами; разрешения локального агента и учётная запись владельца обязательны.

## Проверки

- Базовый `CreateDesktop` / `CloseDesktop`.
- Подтверждение реальной принадлежности тестового процесса отдельному Desktop через `GetThreadDesktop` / `GetUserObjectInformation`. Был найден и устранён случай, когда `subprocess.STARTUPINFO.lpDesktop` игнорировался.
- Полный цикл тестового Win32 приложения с настоящими Edit/Button и проверкой события кнопки.
- PNG-захват без экранного переключения.
- Проверка, что чужой PID / неподходящий класс не принимаются.
- Проверка принудительного завершения собственных дочерних процессов при аварии владельца.
- Unit/contract тесты в `tests/test_isolated_desktop_tools.py`.
