# ASC Game Agent v22: Universal GPU Vision research canary

**Status:** a real Windows Graphics Capture (WGC) → D3D11On12 → D3D12 →
ONNX Runtime DirectML / YOLO-World v2 → GPU compact metadata pipeline
was verified on a **self-owned temporary Win32 window**. It is NOT a
fully autonomous Game Agent or a validated general-game understanding system.
The production Hub 1.2.4 and public CLI 1.1.4 remain unchanged.

**Hub integration (unreleased research branch):** game_agent_open_vocab is a
sixth optional MCP tool. Its local Windows tray toggle is separate from
Game Agent, normal capture and GPU self-test. The toggle is OFF on all
existing installations. It depends on normal capture permission and
resets when capture is disabled. The tool cannot provide custom model paths,
DLLs, prompt embeddings or executable arguments; a native local YES remains
mandatory. It is not activated in the public Hub until release review.

Code: native/game_agent_v22/ (native research source and model tools);
client/asc_game_agent_open_vocab.py (bounded, consent-checked scene adapter);
client/asc_game_agent_scene.py (game-agnostic metadata schema).

## Architecture

1. Select target by HWND, PID and process creation time (Windows Targets v18).
   A different program always requires a native local Yes/No consent dialog.
2. WGC frame remains on the GPU and becomes a 1×3×480×640 float32 tensor.
   The current fast converter maps 16:9 content into a 640×480 model image
   with 60px top/bottom bars. Other aspect ratios are **not supported yet**.
3. YOLO-World v2 consumes the image tensor and an independent
   runtime text embedding tensor of shape 1×8×512.
   Prompts are replaceable without changing YOLO-World model weights.
   GPU inference has ONNX Runtime CPU EP fallback disabled.
4. A GPU compute shader selects one top proposal from 6300 anchors
   per prompt. **Only 256 bytes of metadata per frame** travel GPU→CPU.
   A self-owned fixture additionally reads one diagnostic pixel (4 bytes).
5. The adapter validates the full native capture report, consent scope,
   window fingerprint, no-frame-readback assertions, prompt indices,
   bounding boxes and CPU fallback status. It removes model padding,
   discards weak proposals and emits asc.game_agent.scene.v1.
6. This is object detection only. It does not read UI text, infer
   intent, distinguish NPCs from players or authorize mouse/keyboard input.

| GPU model loaded | RTX 4060 / DirectML |

| Short-test throughput | approximately 25.32 FPS |
| Model output | 1×12×6300 |
| Text features | 8×512 float32 (16 KiB CPU→GPU on initialization) |
| Compact metadata to CPU | 256 bytes/frame |
| Full frames and inference logits to CPU | 0 bytes |
| Inference CPU fallback | Disabled |
| Mouse/keyboard/game process intervention | None |
| Local runtime Doctor and hash verification | Passed |
| Local permissions disabled | Fixture/Capture both denied |
| Real game semantic recognition | NOT VERIFIED |
| OCR, VLM, UI grounding, planner | NOT IMPLEMENTED |

The 25.32 FPS figure is a brief fixture pipeline rate, NOT a game FPS claim.
A plain solid-color window correctly yielded zero detections above threshold.
It does not demonstrate useful object detection accuracy.

## Reproducible source workflow

Requirements: trusted installed Windows Capture v19 development package,
Visual Studio 2022 + CMake + Windows SDK, ONNX Runtime DirectML C++ headers,
Python 3.10+ and offline graph conversion dependencies
onnx 1.17.0 / onnxsim 0.4.36.

1. Copy the current trusted Windows v19 source into a **separate** directory
   named windows-universal-vision-v22-canary. Never edit the sealed v19
   installation. Add the two GPU Open-Vocabulary C++ headers to its include/.
2. Apply native/game_agent_v22/patch_v19.py to the copied directory.
   The script pins and checks the original native source SHA before patching.
3. Independently obtain the ONNX model and run prepare_model.py with a
   source filename and a new output path named
   yolov8s-worldv2-static8-reshape-normalized.onnx.
   Input and output SHA values must match the recorded tested artifacts.
4. Generate exactly eight prompt embeddings with
   generate_text_embeddings.py --output-dir DIRECTORY,
   optionally passing --prompts-json FILE for an arbitrary list of
   eight distinct text prompts. Use a CUDA GPU, such as the server GPU;
   only 16 KiB of text features need to be copied to the Windows PC.
5. Build the copied native CMake project as Windows x64 Release using
   trusted ONNX Runtime DirectML include/lib locations.
6. Create private runtime folder windows-universal-vision-v22-runtime
   containing its compiled native exe, DirectML/ORT runtime DLLs, converted
   ONNX, binary text embeddings, embedding metadata and
   Run-UniversalVision.ps1. Only eight allowlisted files are permitted.
7. Run seal_runtime.py on this directory; it checks hashes, known model,
   prompt tensor shape, and all file names before writing SHA256SUMS.json.
   This is **integrity verification, not a digital code signature**.
   The private wrapper removes its temporary metadata report on exit;
   the only returned result is a bounded, locally validated JSON object.
8. Use Run-UniversalVision.ps1 -Action Doctor for a no-GPU/no-capture
   integrity check. The external-window action is available only after
   the existing local Game Agent permission is explicitly enabled.
   Real capture still requires a native user click on Yes.

Changing a prompt set requires generating new embeddings and sealing a
new private runtime. The native executable has eight runtime prompt slots;
it is **not limited to named game classes**. More than eight simultaneous
prompts and multi-instance NMS are future work.

## Fail-closed behavior and current limits

- External capture requires the saved local enable/capture policies,
  HWND, PID, process start identity and physical local consent.
  Neither the Hub nor Vision model may auto-approve the consent dialog.
- The current GPU preprocessing contract supports **16:9** only.
  Normalization refuses other dimensions until a dynamic-aspect shader
  has been validated.
- YOLO-World raw scores are **uncalibrated**, and only one candidate
  per prompt per frame is emitted. Unknown objects remain unknown.
- OCR, UI grounding, game scene reasoning, memory and action planner
  have not been connected. No automatic input injection is available.
- New v22 was **not** tested on live Palworld. When last checked, the
  user had locally disabled all Game Agent permissions. Do not silently
  re-enable them or bypass the native dialog.
- GPU model validation and screenshot-free, independent external-scene
  semantic tests are required before switching the default from v19.

Next milestones: separately consented unknown-game/desktop-window tests;
multiple proposals + NMS; variable aspect ratio; GPU OCR, VLM and
planner with a separate explicit action-authorization boundary.
