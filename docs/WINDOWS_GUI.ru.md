# Безопасное управление окнами Windows (агент 1.1.1)

В одной интерактивной сессии Windows все приложения используют общий указатель мыши и общее активное окно. Поэтому прежние координатные клики и ввод «в текущее окно» могут мешать пользователю. **ASC Remote Hub 1.1.1 по умолчанию блокирует такие действия.**

## Адресная работа через UI Automation

1. `window_list` выдаёт HWND, PID, заголовок и координаты окна.
2. `window_controls` читает дерево элементов строго указанного окна. Нужно передать HWND, `expected_pid` и `title_contains`. Курсор и клавиатура не используются.
3. `window_action` выполняет действие только над **единственным** найденным элементом по точному `automation_id` либо `name`. Дополнительные фильтры: `control_type`, `class_name`. Методы: `invoke`, `set_value`, `toggle`, `select`, `expand`, `collapse`.

Пример вызова `window_controls` (ID устройства, HWND, PID условные):

```json
{
  "device": "d_<из-list_devices>",
  "hwnd": 123456,
  "expected_pid": 4242,
  "title_contains": "Блокнот",
  "limit": 70,
  "depth": 6
}
```

После нахождения подходящего элемента:

```json
{
  "device": "d_<из-list_devices>",
  "hwnd": 123456,
  "expected_pid": 4242,
  "title_contains": "Блокнот",
  "selector": {
    "automation_id": "TextEditor",
    "control_type": "Edit"
  },
  "action": "set_value",
  "value": "Проверочный текст"
}
```

Если элемент не найден, неоднозначен или не поддерживает действие, инструмент возвращает ошибку. **Автоматического перехода к физическому клику нет.** Парольные поля недоступны.

## Защита работающего пользователя

Некоторые приложения самостоятельно перехватывают фокус при обращении через UI Automation. Это было воспроизведено на WPF.

- По умолчанию `window_action` разрешается, только если пользователь не работал с мышью и клавиатурой **не менее 45 секунд**. Проверка выполняется перед вызовом и непосредственно перед действием.
- Если окно неожиданно перехватило фокус, возвращается `UIA_FOCUS_INTERFERENCE`, а повторные UIA-действия с этим HWND/PID блокируются до перезапуска агента.
- Только просмотр `window_controls` не требует ожидания простоя.
- Оператор может настроить локальный параметр `ASC_RC_UIA_ALLOW_ACTIVE_USER=1`, но это снимает защиту пользователя. По умолчанию параметр выключен.

Фоновое UI Automation **не гарантирует абсолютной независимости** от интерактивной сессии: результат зависит от приложения. Для одновременной полноценной работы человека и агента нужен отдельный Windows-сеанс/рабочий стол либо API приложения.

## Старые средства ввода

`click_mouse`, `type_text`, `press_keys`, `scroll_mouse`, `terminal_send`, `window_focus` в Windows **запрещены по умолчанию** даже при полном доступе агента.

Для их включения администратор должен локально задать `ASC_RC_ALLOW_INTERACTIVE_GUI=1` и отдельно разрешить вмешательство в конкретном вызове через `allow_desktop_interference=true`. Обязательны точные HWND, PID и часть заголовка. Клавиатурный/мышиный ввод допустим только в уже активное окно. Самовольное переключение фокуса комбинацией Alt больше не применяется.

Не включайте интерактивный режим, если за компьютером продолжает работать человек.

## Ограничения и проверки

- Electron, Chromium, игры и другие приложения с нестандартной графикой могут не предоставлять доступных элементов UI Automation. Ошибка не является разрешением нажать в приблизительные координаты.
- `window_screenshot` пока захватывает прямоугольник с экрана, который может содержать перекрывающие окна. Для адресных действий важнее дерево UI Automation.
- Отправка `invoke` не доказывает завершение операции приложения. Проверяйте состояние после действия; `set_value` проверяет текст там, где это поддерживается.
- `run_command` работает с правами пользователя ОС и не ограничивается GUI-защитой: доступ к выполнению команд следует выдавать осознанно.

Обновление: `npx --yes https://hub.example.com/cli.tgz`. Версия агента **1.1.1**. После обновления проверьте `machine_info.agent_version` и выполните обновление списка MCP-инструментов в приложении.

Тесты находятся в `tests/test_gui_safety.py`. Не проверяйте физические клики на рабочем столе, за которым сейчас работает человек.

## Нативное управление интерфейсом через дерево доступности

ASC Remote Hub может использовать нативный движок agent-desktop
(версия 1.3.1, лицензия Apache-2.0, проект vercel-labs/agent-desktop).
Это не нейросеть и не отдельный постоянно работающий агент:
движок запускается по требованию без Node.js и обрабатывает дерево
Windows UI Automation, а не скриншоты.

Опциональная установка на компьютере Windows (без перепривязки):

    python install/setup_native_desktop.py

Установщик загружает официальный архив с GitHub Releases, сверяет
SHA-256 архива и извлечённого EXE, затем размещает бинарник
в каталоге bin действующего агента. До следующего запуска агента
новые инструменты не появляются в списке.

Порядок работы:

1. desktop_windows(device): получить нативный идентификатор окна w-...;
2. desktop_snapshot(device, window_id="w-...", skeleton=true):
   компактное представление дерева доступности с ссылками @s...:eN;
3. desktop_snapshot(device, root="@s...:eN"): подробно изучить
   нужную ветку; либо desktop_find с role и name;
4. desktop_act(device, ref="@s...:eN", action="click"):
   выполнить семантический UIA-вызов. Для текстового поля используйте
   action="set-value" и value. Поддержаны также type, clear, check,
   uncheck, select, toggle, expand, collapse;
5. desktop_get или новый desktop_snapshot: убедиться в результате.

Движок сам проверяет идентичность элемента, пригодность к действию
и устаревшие ссылки, возвращая в JSON ошибки вроде STALE_REF
и AMBIGUOUS_TARGET. У Remote Hub отключены физические режимы headed,
передача произвольных CLI-аргументов, команды со скриншотами и
отладочные артефакты. Текущая локальная политика неактивности
пользователя продолжает блокировать изменяющие действия.

Данные дерева доступности могут быть личными. Они хранятся
в отдельном локальном хранилище внутри каталога состояния агента;
старые снимки дерева ограничены 32 экземплярами. Снимки экрана
не создаются, CLI не запускается в shell, секреты из ответов
не сохраняются в аудите и не попадают в исходники проекта.

При отсутствии проверенного бинарника прежние window_controls
и window_action продолжают работать. Движок не устанавливается
принудительно и не включается в публичные архивы агента.
Официальный источник и лицензия:
https://github.com/vercel-labs/agent-desktop
## Сеансы, ожидание, пакетные действия и управление окнами

Расширение поверх проверенного нативного agent-desktop v1.3.1.
Скриншоты и физическое управление курсором не используются.

- desktop_session(start, name="task"): создаёт изолированное пространство
  snapshot/ref. Для защиты персональных данных автоматически указывается
  --no-trace. Передайте возвращённый session_id во все следующие вызовы.
  desktop_session(end, session_id) закрывает сеанс;
  desktop_session(gc, older_than_seconds=86400) очищает только завершённые.
- desktop_surfaces(app): показывает доступные меню, диалоги и другие слои
  интерфейса. desktop_snapshot(surface="menu"|"sheet"|"alert"|...) и
  desktop_find(surface="menu", role="menuitem", name="...") читают слой
  независимо от родительского окна.
- desktop_wait(mode="element"|"window"|"text"|"menu"|"menu-closed"|
  "event"|"notification"): ждёт реальное изменение UI, а не фиксированное
  время; лимит до 30 секунд.
- desktop_act(wait_for="button:Done" | wait_for_gone="progressindicator"):
  нативное действие и ожидание последующего UI в одном вызове.
  Запрашивайте новый snapshot после изменения UI. Native result.disposition
  различает not_delivered, delivery_uncertain, delivered_unverified и
  delivered_verified. Повторять небезопасные/неизвестные действия запрещено.
- desktop_verify(ref, value): сверяет значение текстового поля в RAM
  без передачи ожидаемой строки в аргументах процесса и без возврата
  содержимого поля. Для паролей приложение может запретить чтение значения.
- desktop_apps(operation="list"|"launch"|"close", app="..."):
  список приложений, запуск по зарегистрированному имени, мягкое закрытие.
  Произвольные командные строки и принудительное завершение запрещены.
- desktop_window(operation="move"|"resize"|"minimize"|"maximize"|"restore"|
  "focus", window_id="w-..."): нативное управление окнами. Изменения
  допускаются лишь при соблюдении локальной политики простоя пользователя.
- desktop_batch(steps=[{"op":"find","args":{...}}, ...]):
  1–12 типизированных последовательных шагов с общим лимитом 60 секунд.
  Ссылка из одного find может передаваться в следующий act через
  {"ref_from":0}. Операция не является транзакцией, предыдущие действия
  не откатываются; при небезопасном результате выполнение прерывается.

Пример: изолировать сеанс, найти точную кнопку, выполнить действие,
ожидать появления элемента и повторно считать дерево доступности.

**Безопасный ввод.** Для действий set-value и type строка передаётся
через stdin, никогда через аргументы CLI. Это снижает риск утечки через
список процессов. Действие select использует обычную подпись пункта
в аргументах, поэтому туда нельзя передавать секреты. Имена элементов,
текст поисковых предикатов и названия окон также не должны содержать
секретов. Локальный аудит Remote Hub записывает только хеш аргументов.

Каждый инструмент типизирован; команды shell, произвольный ввод,
--headed, --screenshot, --trace, отладочные артефакты и координатный
режим недоступны через эти MCP-команды. Старые UIA-инструменты сохранены.
## Ускоренный C API (опционально)

Оригинальная библиотека agent_desktop_ffi.dll той же версии v1.3.1,
проверенная по SHA-256 архива и DLL. Установка из официального релиза:

    python install/setup_native_desktop.py --ffi
    python install/setup_native_desktop.py --ffi --check

При установке никакие ключи и конфигурация Remote Hub не меняются.
Параметр engine="ffi" в desktop_status, desktop_snapshot и desktop_act
использует C API в текущем процессе без запуска EXE для каждого вызова.
Обычный режим engine="cli" остаётся по умолчанию и не требует DLL.

Ограничения C ABI v7: снимок дерева поддерживает только указанное
приложение или передний план и системную поверхность, но не window_id,
skeleton или root. Проверку появления элементов после действия следует
делать отдельным desktop_wait. Для полного дерева, контекстного просмотра
и post-action wait используется обычный CLI. C API применяет
те же строгие ссылки и политику Headless, без физического ввода.
При наборе текста значение передаётся через память C API, не через argv.
Поля с текстом результата редактирования маскируются перед ответом.

Тест на Windows подтвердил корректность ABI 7 и работу с реальным
деревом. Отдельный вызов status: FFI около 15 мс, CLI около 170 мс.
Снимок дерева: оба режима около 700 мс в проверенном приложении.
Ускорение не гарантируется для всех задач и зависит от приложения.


### Подтверждение действий и безопасный выбор

Начиная с агента 1.1.8, desktop_batch завершает сценарий ошибкой,
если desktop_verify / desktop_wait сообщает ok=false либо отсутствует
совпадение. Второй изменяющий шаг нельзя выполнять, пока результат
предыдущего не подтверждён отдельным desktop_wait или desktop_verify.
Действие с delivery=delivered_verified считается подтверждённым.
Последний неподтверждённый шаг возвращает
ok=false и verification_required=true. Действия не повторяются автоматически.

Нормализованное поле select не передаётся через CLI аргументы:
у исходного CLI select отсутствует --stdin. Поэтому выбор запускается
через проверенную C API DLL, где текст передаётся в память процесса,
а ответ очищается от значений полей. Если DLL недоступна, возвращается
SELECT_REQUIRES_FFI (действие не отправлено). Не все приложения
поддерживают SelectionItemPattern: ACTION_NOT_SUPPORTED остаётся
отказом без перехода к глобальной мыши или клавиатуре. Для приложений
с доступным пунктом в дереве UI Automation можно найти его по роли
и вызвать отдельное семантическое действие.

Тайм-ауты пакетных операций изолированы по потокам. Разные сеансы
не перезаписывают ограничения времени друг друга. Создание C API
осуществляется под блокировкой; параллельное чтение интерфейса
проверяется раздельно. Состояние пользователя и внутренние пути
не включаются в публичный репозиторий.
